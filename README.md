# WebPix Optimizer for WordPress

Speed up your WordPress website with automatic asset delivery through WebPix CDN.

WebPix Optimizer is a WordPress performance plugin that connects your website to WebPix CDN and automatically rewrites supported public frontend asset URLs for optimized delivery.

Instead of serving supported frontend assets directly from your WordPress server, the plugin generates WebPix delivery URLs and routes requests through the WebPix infrastructure.

This allows WebPix to process and deliver website assets while your original files remain hosted on your WordPress installation.

**Website:** https://webpix.io

## Why use WebPix Optimizer?

WordPress websites can contain thousands of frontend assets including Media Library images, featured images, post content images, WooCommerce product images, banners, theme resources and other public files.

Serving all assets directly from the origin server can increase page weight, bandwidth usage and asset delivery time — especially on image-heavy websites and ecommerce stores.

WebPix Optimizer integrates WebPix into the WordPress frontend delivery process.

Once configured, supported public frontend asset URLs are automatically rewritten to WebPix URLs without requiring you to manually change every post, page or theme template.

This makes WebPix particularly useful for existing WordPress websites where manually modifying content or replacing large numbers of asset URLs would be impractical.

## How it works

WebPix Optimizer works between your WordPress frontend and WebPix CDN.

The basic request flow is:

```text
Visitor
   ↓
WordPress website
   ↓
WebPix Optimizer
   ↓
WebPix CDN URL
   ↓
WebPix
   ↓
Original public WordPress asset
   ↓
Visitor
```

When WordPress generates a supported public frontend asset URL, WebPix Optimizer can rewrite that URL to use WebPix delivery.

The original asset must remain publicly reachable because WebPix needs to access the source file.

## Features

### Automatic frontend URL rewriting

WebPix Optimizer automatically rewrites supported public frontend asset URLs generated by WordPress.

There is no need to manually edit every post, page or theme template just to replace existing asset URLs.

### WebPix CDN integration

The plugin connects your WordPress website to WebPix CDN.

Once WebPix credentials are configured and the plugin is enabled, supported frontend assets can be delivered through WebPix instead of directly from the origin server.

### Centralized configuration

WebPix settings are managed from the WordPress administration panel.

This gives administrators a central place to configure the WebPix integration without manually editing WordPress content.

### Existing website support

WebPix Optimizer can be added to an existing WordPress website.

Because supported URL rewriting happens during frontend delivery, existing content does not need to be manually rewritten before WebPix can be used.

### Original assets remain on your website

WebPix Optimizer does not require you to move your original assets away from WordPress.

Your WordPress installation remains the source of the original files while WebPix provides the delivery layer.

## Installation

### 1. Upload the plugin

Log in to your WordPress administration panel and go to:

```text
Plugins > Add Plugin
```

Click:

```text
Upload Plugin
```

Select the WebPix Optimizer ZIP package and upload it.

### 2. Install the plugin

Click:

```text
Install Now
```

Wait until WordPress finishes installing the plugin.

### 3. Activate WebPix Optimizer

After installation, click:

```text
Activate Plugin
```

Alternatively, go to:

```text
Plugins > Installed Plugins
```

Find:

```text
WebPix Optimizer
```

and click **Activate**.

### 4. Configure WebPix

Open the WebPix Optimizer settings in the WordPress administration panel.

Enter the required WebPix credentials and enable the integration.

Save the configuration.

### 5. Clear cache

If your WordPress website uses a caching plugin, server cache, reverse proxy or CDN cache, clear it after enabling WebPix Optimizer.

You may also need to clear:

- Page cache.
- Object cache.
- Theme cache.
- Server-level cache.
- Reverse proxy cache.
- Existing CDN HTML cache.

Then reload the frontend and verify that WebPix URLs are being generated.

## Configuration

Open the WebPix Optimizer settings in WordPress.

Enter the WebPix credentials associated with your account.

Enable the plugin's optimization/delivery functionality and save the configuration.

After changing WebPix settings, clear any active frontend cache before checking the generated website HTML.

## Verify installation

After installation, open the frontend of your WordPress website.

Check several different page types, for example:

```text
Homepage
Page
Blog post
Category/archive page
WooCommerce shop page
WooCommerce product page
```

Only check WooCommerce pages when WooCommerce is installed on the website.

Open your browser Developer Tools.

In Chrome or Chromium-based browsers:

```text
F12 > Network
```

Reload the page and inspect frontend asset requests.

Supported assets processed by WebPix Optimizer should use WebPix delivery URLs instead of their original direct WordPress URLs.

You can also inspect the generated page source:

```text
Ctrl + U
```

and search for:

```text
webpix
```

This is a quick way to determine whether WebPix URLs are present in the generated frontend HTML.

## Public asset accessibility

WebPix must be able to access the original WordPress assets.

For example, a Media Library asset may be available at a URL similar to:

```text
https://example.com/wp-content/uploads/2026/08/example.jpg
```

That URL must be publicly reachable.

WebPix cannot process an origin asset if access to the original URL is blocked.

Check this especially when your website uses:

- HTTP authentication.
- IP restrictions.
- Firewall rules.
- Bot protection.
- Hotlink protection.
- Security plugins.
- CDN security rules.
- Cloudflare security rules.
- Custom Nginx or Apache access restrictions.

## WordPress Media Library

Existing files in the WordPress Media Library can remain stored in their normal location.

For example:

```text
/wp-content/uploads/
```

WebPix Optimizer does not require you to manually replace Media Library files simply to change their frontend delivery URLs.

This is particularly useful for websites that already contain thousands of uploaded images.

## Troubleshooting

### WebPix URLs do not appear

If original WordPress URLs are still being generated:

1. Confirm that **WebPix Optimizer** is installed.
2. Confirm that the plugin is activated.
3. Open the WebPix Optimizer settings.
4. Verify the required WebPix credentials.
5. Confirm that WebPix integration is enabled.
6. Save the configuration.
7. Clear all relevant WordPress and server caches.
8. Reload the frontend.
9. Inspect page source and Network requests again.

### Plugin is active but nothing changes

First verify that the frontend page is not being served from an old cache.

Clear:

- WordPress page cache.
- Server cache.
- Reverse proxy cache.
- CDN HTML cache.

Then reload the page and inspect the generated HTML again.

### WebPix cannot access an asset

Copy the original asset URL and open it directly in a browser.

For example:

```text
https://example.com/wp-content/uploads/2026/08/example.jpg
```

The URL should be publicly accessible without:

- Authentication.
- Login.
- Private network access.
- IP allowlisting.

If the original file cannot be accessed publicly, WebPix may not be able to retrieve it.

### Some assets are rewritten and others are not

Check how the affected assets are generated.

They may come from:

- WordPress core.
- The active theme.
- A page builder.
- WooCommerce.
- Another plugin.
- Inline CSS.
- JavaScript.
- AJAX requests.
- Dynamically generated frontend content.

Assets generated outside the supported WordPress integration flow may require separate handling.

### Changes do not appear after saving

Clear all relevant cache layers and perform a hard browser refresh.

In Chrome:

```text
Ctrl + Shift + R
```

Also test in an incognito/private browser window to reduce the chance of seeing cached frontend content.

### Website works without WebPix but has problems when enabled

Temporarily disable WebPix Optimizer.

Go to:

```text
Plugins > Installed Plugins
```

Find:

```text
WebPix Optimizer
```

and deactivate it.

Clear the frontend cache and test the website again.

If the problem disappears, investigate compatibility with the active theme, page builder or another frontend optimization plugin.

## Disable WebPix Optimizer

WebPix Optimizer can be temporarily disabled without deleting the plugin.

Go to:

```text
Plugins > Installed Plugins
```

Find **WebPix Optimizer** and click:

```text
Deactivate
```

Clear the frontend cache and reload the website.

Because the original assets remain on the WordPress installation, disabling the plugin does not require rebuilding the Media Library.

3. Update or install the new plugin version.
4. Confirm that WebPix Optimizer is activated.
5. Open its settings.
6. Verify the WebPix configuration.

- Public theme files.

- Public Git repositories.
- Screenshots.
- Public documentation.

4. Save configuration
5. Clear WordPress cache

- Request URL.

## Frequently Asked Questions

### Does WebPix Optimizer modify my original WordPress files?

The original public assets remain hosted by your WordPress installation.

WebPix Optimizer changes supported frontend delivery URLs rather than requiring you to manually replace every source asset.

### Do I need to manually change existing posts and pages?

For supported URL rewriting, no.

The purpose of the plugin is to integrate WebPix into frontend delivery without requiring manual replacement of every supported asset URL stored in existing content.

### Does WebPix work with existing Media Library files?

Existing public Media Library files can remain in their normal WordPress location and act as origin assets for WebPix delivery.

### Does WebPix need access to my original files?

Yes.

Original assets must be publicly reachable so WebPix can retrieve them.

### Can I use WebPix with WooCommerce?

WebPix Optimizer can be used on WordPress websites that run WooCommerce, but the storefront should be tested with the specific WooCommerce theme and extensions installed on the website.

### Do I need to edit my WordPress theme?

For supported frontend URL rewriting, the plugin is intended to integrate with WordPress without requiring you to manually replace every asset URL in theme templates.

Custom themes and unusual asset-generation methods should still be tested.

### Why do I still see original URLs?

Possible causes include:

- Cached HTML.
- Assets generated by another plugin.
- Page builder output.
- Inline CSS.
- JavaScript-generated URLs.
- AJAX-loaded content.
- Unsupported frontend output.
- WebPix Optimizer not being enabled or configured correctly.

Clear caches first, then inspect where the affected URL is being generated.

### Can I disable WebPix without losing my Media Library?

Yes.

Your original WordPress assets remain available on your server.
